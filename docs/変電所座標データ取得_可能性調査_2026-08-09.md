# 変電所の座標データ取得 可能性調査

**調査日**: 2026-08-09
**調査範囲**: 調査のみ（microCMS 書込ゼロ・データ変更ゼロ）
**背景**: `/grid` の地図表示は中部エリアでしか出せない。当方 substations 8,225件のうち **座標があるのは 1,081件（中部のみ）**、残り 7,144件は緯度経度なし。全国展開の前提条件として座標の入手可能性を実査した。

**結論（先に）**: **9社すべて座標を公表していない。公的オープンデータにも変電所データセットは存在しない。OpenStreetMap は件数こそ足りるが、ODbL の share-alike が当サイトの空き容量データにまで及ぶため採用不可。合法かつ商用利用できるソースで埋まるのは 8,225件中 41件（0.50%）にとどまる。**
→ **「データを取ってきて全国地図を作る」という筋は、現時点で閉じている。**

---

## 0. 判定基準の確立（中部はなぜ座標を持てているのか）

microCMS の中部レコード100件を実査したところ、全件が座標を保有し、`source_url` は
`https://gridmap.powergrid.chuden.co.jp/geo_data/KRSIH016`、`data_source_format` は `CSV` だった。

さらに実地検証したところ、**同じ `geo_data/` 配下の `KRSIH001` が gzip 圧縮された GeoJSON** であり、
展開すると 3,647,382 文字・`coordinates` 配列 6,632 個（lon, lat 順）を含むことを確認した
（gzip マジックバイト `1f 8b 08 08`、内部名 `KRC50010_01.cat`。抽出座標例 136.911265/35.164986 など、いずれも中部管内）。

> **中部のパターン** = 自社 WebGIS（`gridmap.powergrid.chuden.co.jp`）を持ち、そのフロントエンドが
> 座標入りデータファイルを `geo_data/` エンドポイントから読み込んでいる。
> （Gr2 調査で公表日を取得した `geo_data/KRSIH002` も同じ仕組み）

したがって他社の判定基準は **「WebGIS があるか、あるならそのフロントが読むデータに座標が含まれるか」** となる。

### 判定の根拠（要点）

- **東京電力**: `/pg/consignment/system/` を取得しリンクを全抽出したが、地図データ系は静的イメージマップ（`jquery.rwdImageMaps.js`）のみ。`zonemap/js/search.json` は存在するが中身は**工業団地27件**で lat/lng なし。`gridmap.tepco.co.jp` 等の中部型サブドメインは接続不能。CSV のヘッダは「変電所No/変電所名/電圧/台数/設備容量/運用容量値/予想潮流/空容量/N-1電制…」で**座標列も住所列もなし**。
- **関西電力**: マッピングPDFは変電所名・地名がすべて**ラスタ画像**に焼かれており、pdftotext で抽出できる CJK はゼロ。埋込フォントは Meiryo UI / Calibri のみ。さらに CSV の変電所No は「北A」のように CJK 接頭辞つきだが PDF 側からは "A" しか取れず、**シートと変電所を機械的に突き合わせられない**。なお `welcome-zone-map/js/data.json` に lat/lng を持つ JSON が1本あるが、対象は需要地誘致用の工業用地7件で変電所ではない。
- **東北電力**: 「系統状況マップ」は WebGIS ではなく `<area shape="rect" coords="572,107,586,123">` の静的イメージマップ。**この coords は画像内ピクセルであって地理座標ではない**（誤読注意）。
- **各社共通**: OCCTO の公式マッピングリンク集（`occto.or.jp/access/link/mapping.html`）を確認しても、WebGIS を登録している社は中部以外に存在しない。

## 2. 公的オープンデータの評価

### 2-1. 国土数値情報 — **変電所データセットは存在しない**

電力関連は `P03 発電施設` **のみ**で、変電所は含まれない。3通りで確認した。

1. データ説明の「内容」欄に列挙されるのは水力・火力・地熱・原子力・風力・太陽光・バイオマス・複合型の**発電施設のみ**
2. メタデータXMLの abstract も「電力供給源（発電施設）の位置…」
3. 実データ `P03-13.zip`（1,402,115 bytes）を取得し SHP を列挙 → 9レイヤすべて発電系（Biomass / Hydroelectric / Nuclear / Geothermal / Photovoltaic / PumpedStorage / Thermal / PowerPlantComplex / WindPower）。**変電所レイヤは存在しない**

さらにデータセット索引を全文検索して「変電」0件、「送電」0件、「電力」0件。

> **★ライセンス上の重大な論点**: P03 は **非商用**。
> 「非商用目的のみでの利用（ただし複製物の再配布を除く）が可能なもの」＝**商用サイトでは使えず、再配布も不可**。
> 仮に変電所データがあったとしても、当サイトでは使えなかった。

### 2-2. 不動産情報ライブラリ API — **電力系APIは存在しない**

APIマニュアル全文（86,638 bytes）を取得して走査したところ、**「電」の字が0回**。35のAPI（不動産価格・用途地域・学校区・医療機関・災害危険区域など）に電力設備系は一切ない。

### 2-3. 基盤地図情報 — **変電所は含まれない**

- まず訂正: `https://fgd.gsi.go.jp/` は**存在しない**（NXDOMAIN）。正しくは `https://service.gsi.go.jp/kiban/`
- 維持されている10項目（測量基準点／海岸線／行政区画／道路縁／軌道中心線／標高点／水涯線／**建築物の外周線**／町字境界／街区境界）に**施設分類が一切ない**
- 建築物は「普通建物／堅ろう建物／普通無壁舎／堅ろう無壁舎」の4種のみで、**名称も用途属性も持たない**。変電所の建屋が入っていても識別できない
- ダウンロードは利用者登録制

### 2-4. 国土地理院 地理院地図Vector（ベクトルタイル）— **ライセンスは合格、データが足りない**

**全国 z14 タイル 138,978枚を全数走査**した（GSI公式のタイル目録 `mokuroku.csv.gz` から z14 の全リストを取得。取りこぼし0・デコードエラー0）。

| 項目 | 実測値 |
|---|---|
| `ftCode 8103 発電所等`（点） | 8,501 → 重複除去 **7,827点** |
| うち名称を持つもの | **0**（属性は `orgGILvl` と `ftCode` のみ） |
| `annoCtg 653`（注記レイヤ）ラベル | 592 → **546件** |
| うち名称に「変電所」を含むもの | **62件** |

- **発電所と変電所は同じ記号**（GSI 明言:「発電所等の記号は、発電所と変電所を表示しています」）。仕様書を全ズーム分読んでも、bvmap の電力語彙は `8103 発電所等` / `8205→8202 送電線` / `annoCtg 653 発電所` の**3つだけ**で、変電所専用コードは存在しない
- **記号とラベルの空間結合は不可能**。62件のラベルから最寄りの 8103 記号までの距離は**中央値 3,421m・最大 9,949m**（500m以内は4件のみ）。ラベルは文字配置のアンカーであって施設点ではない
- 後継の「最適化ベクトルタイル」も同じ上限（デコードして確認済み）

**ライセンスは明快に合格**:
- 提供実験のベクトルタイルは**基本測量成果ではない**と明記されており、**測量法29条/30条の複製・使用承認は不要**
- 国土地理院コンテンツ利用規約 → 公共データ利用規約 PDL1.0 → **「商用利用も可能です」**、share-alike なし
- 義務は出典表示（「出典：国土地理院ウェブサイト（URL）」＋「国土地理院ベクトルタイル提供実験」）と改変した旨の記載
- ただし**実験公開**であり「URL やデータ構成が変わる可能性」「提供実験終了までの期間」と明記＝**基盤に据えるべきではない**

### 2-5. 国土地理院 地名情報（地理院地図 地名検索API）— **現時点で唯一使える公的ソース**

`msearch.gsi.go.jp` から**変電所86件**を名称＋緯度経度つきで取得できた。PDL1.0（商用可・share-alike なし・出典表示のみ）。

## 3. OpenStreetMap の評価

### 3-1. 件数と品質（実測）

Overpass API（`overpass-api.de`）で実クエリを実行:

```
[out:json][timeout:240];
area["ISO3166-1"="JP"][admin_level=2]->.a;
(node["power"="substation"](area.a);
 way["power"="substation"](area.a);
 relation["power"="substation"](area.a););
out count;
```

→ **6,212件**（node 135 / way 6,051 / relation 26）。way が97%＝ポリゴンなので点座標には `out center;` で重心を取る必要がある。

タグ充足率（全6,212件で計測）:

| タグ | 件数 | 率 |
|---|---|---|
| `name` | 3,620 | 58.3% |
| `voltage` | 3,637 | 58.5% |
| `operator` | 3,212 | 51.7% |
| name + voltage + operator が揃う | **2,404** | **38.7%** |
| **名称なし** | **2,592** | **41.7%** |

名称は `name:ja` ではなく **`name` に日本語で入っている**（名称保有3,620件のうち99.8%が日本語、3,297件が「変電所」で終わる）。

### 3-2. 法務論点（★最重要）

**ODbL 1.0 の share-alike が、当サイトの空き容量データにまで及ぶ。**

ODbL の定義（§1.0）:
- **Derivative Database** — 「the Database に基づくデータベース。翻訳・翻案・改変、または実質的部分の抽出・再利用を新たなデータベースに行うことを含む」
- **Collective Database** — 「**改変されていない（unmodified）**当データベースを、それ自体で**独立した（independent）**データベースの集合の一部として組み合わせたもの」→ これに該当すれば Derivative ではない

そして OSMF 理事会が2016-06-17に承認した **Collective Database Guideline** が、判定基準と**まさに当方と同型の反例**を示している。

> 判定基準: 「OSMデータと非OSMデータを単一のデータベースに結合したものは、**同一の地域区分において、あるデータ型のデータが全てOSMか全て非OSMのいずれかである限り**、独立（＝Collective Database）とみなされる」

> 反例: 「ある国のレストランの独自リストを持っているとする。これを OpenStreetMap の対応データで補完し、その過程で重複オブジェクトを除去したい。**結果として得られる結合データベースは本ガイドラインの対象外であり、公開利用する場合、独自データが ODbL の share-alike の対象となりうることを考慮しなければならない**」

「レストラン」を「変電所」に置き換えると、当方の計画（8,225件の独自変電所リストを OSM の対応データで名寄せ補完する）とそのまま一致する。

さらに:
- §4.4(c) により、そのデータベースから作った Produced Work を公開利用した時点でデータベース本体が引き込まれる
- Produced Work Guideline の判定基準は「**元データの抽出を意図しているか**」であり、**公開検索可能なデータベースはProduced Workではなくデータベースと分類される**。`/grid/search` を持つ当サイトはこれに該当する
- §4.6 により、要求があればデータベース全体を提供する義務が生じる

**義務となる出典表示**（仮に採用した場合）:
- 「OpenStreetMap」への帰属表示が必須（「© OpenStreetMap contributors」も可）
- ODbL であることを明示し、`openstreetmap.org/copyright` へリンク
- 「地図や成果物を見る人全員に提示され、操作しないと見えない形は不可」

### 3-3. 判定: **採用しない（AVOID）**

理由は出典表示の手間ではなく、**share-alike が当サイトの中核資産（空き容量データ）に及ぶこと**。
費用対効果でも見合わない — 名寄せで埋まるのは 7,144件中 **3,287件（46%）** にとどまり、半分以上は別途手当てが必要。加えて41.7%が無名、`operator` は約10社に対して178通りの表記ゆれ（2020年の法的分離前後の社名が混在）、`voltage` はセミコロン区切りの自由文、BESS連系で重要な100kV以上は**約964件しかない**。

## 4. 名寄せ可能性の評価（当方8,225件 × 合法クリーンな候補95件）

候補 = 国土地理院 地名情報 86件 ＋ Wikidata の重複除去後 9件 = **95件**。
当方データは 8,225件（ユニーク名 6,394 / 「変電所」等の接尾を落とした核名 6,034）。

| 指標 | 実測 |
|---|---|
| 名称が一致した候補 | **70 / 95**（完全一致22・接尾を落とした核名一致48） |
| **1対1で確定できる** | **41件** |
| 同名が複数レコードに当たる（曖昧） | **29件**（うち**県をまたぐ11件は自動確定不能**） |
| **座標が入る当方レコード** | **41件 / 8,225件 = 0.50%** |

**曖昧さは実在する問題**。例えば「湖南変電所」は**北海道と長野県の両方**に、「高松変電所」は三重県・島根県ほか計4件に当たる。座標を持たない側を名前だけで結ぶと、北海道の変電所に長野の座標を入れてしまう。距離による絞り込みは「当方に座標がないから照合できない」ため使えず、**この29件は原理的に自動解決できない**。

**位置精度**は良好: 同名が引ける2件で照合したところ、駿遠変電所 161m、東名古屋変電所 162m の誤差。地図ピンには十分だが、精密用途には不足。

**参考**: OSM を使えば 3,287/7,144 = 46.0% が埋まるが、§3の法務理由で不採用。

## 5. 結論と選択肢

### 確定した事実

1. **10社中9社は座標を公表していない**。中部型の WebGIS を持つ社は他に存在しない
2. **公的オープンデータに変電所データセットは存在しない**（国土数値情報・基盤地図情報・不動産情報ライブラリ・G空間情報センター・自治体ポータル、いずれも該当なし）
3. **合法かつ商用可のソースで埋まるのは 0.50%**（41件／8,225件）
4. **OSM なら 46% 埋まるが、share-alike が空き容量データに及ぶため採用不可**
5. **住所からのジオコーディングも成立しない** — 大字レベルの住所が得られるのは中国電力の40件のみ。関西の「シート＝複数市町村」、九州の「地区＝2〜4市町村」は原理的に点にならない

### 取りうる選択肢（推奨順）

**A案: 全国地図は作らず、中部地図を維持したまま別の価値で勝負する（推奨）**
座標が1%未満しか埋まらない以上、「全国の変電所地図」は成立しない。中途半端に点が散る地図はむしろ「データが欠けている」印象を与える。現状の中部限定マップ＋県別一覧の構成を維持するのが最も誠実。

**B案: 主要変電所だけの「基幹系マップ」に目的を変える**
国土地理院 地名情報の41件（曖昧11件を除く）＋中国電力の大字住所40件をジオコーディング＝**最大80件強**。「全国の変電所」ではなく「**基幹系の主要変電所**」と位置づければ、件数が少なくても意味のあるコンテンツになる。出典表示（「出典：国土地理院ウェブサイト」＋改変した旨）が必要。ベクトルタイルは実験公開のため、使うなら地名情報API側を採る。

**C案: 手作業で座標を付与する**
1件あたり数分として 7,144件は現実的でない。仮にやるなら 100kV以上の基幹系に絞る（OSM の統計では全国で約964件相当）。江田さん1人運営の体力を考えると推奨しない。

**D案: 各社に座標データの公表を要望する**
中部電力パワーグリッドが既に GeoJSON を公開している実績があるため、要望自体は筋が通る。ただし実現時期は制御できない。

### 実務上の注記

- 国土地理院 地名情報を**自社DBに保存**する場合、リアルタイムのタイル読込とは別論点になる。ベクトルタイルは「基本測量成果ではない」と明記されているため測量法の承認は不要だが、地名情報APIの保存利用については**一行の事前確認を入れておくと安全**（対象は86件の公開地名でリスクは低い）
- OSM を「地図の背景タイル」として表示するだけなら share-alike は発生しない（Produced Work にとどまる）。**座標を自社DBに取り込んで結合すること**が問題であり、背景地図としての利用とは切り分けて考える
