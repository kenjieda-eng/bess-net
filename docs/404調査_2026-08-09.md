# GSC 404（1,086ページ）の原因調査

**調査日**: 2026-08-09
**調査範囲**: 調査のみ（修正ゼロ・microCMS 書込ゼロ）
**背景**: GSC Coverage で「見つかりませんでした（404）」が **1,086ページ**（確認: 失敗）と報告されている。

---

## 結論（先に）

**③「sitemap に載っているのに404」は 0件。①の既存301はすべて正しく動作している。実害は小さい。**

そして **1,086件の主犯は、意図的に消した旧ニュースURLが返す 410 Gone** である可能性が高い。
GSC は 410 を「見つかりませんでした（404）」に合算して報告するため、**設計どおりの挙動が404として集計されている**。

ただし率直に申し上げると、**GSC が404と報告している実URLの一覧が手元にないため、1,086件の内訳を実測で確定させることはできていない**。
本レポートは「サイト側に問題があるか」を全数・網羅で検査したものであり、**サイト側に修正すべき欠陥は見つからなかった**という結論である。
1件単位で潰したい場合は、GSC の「見つかりませんでした（404）」からURLをエクスポートしていただければ、突合して確定できる。

---

## 1. 検査したこと と 結果

### 1-1. 既存の301統合は正しく動いているか → **全件 正常**

| 対象 | 件数 | 実応答 | 判定 |
|---|---:|---|---|
| glossary 重複統合の301元 | 143 | **全件 301** | ✓ |
| projects 重複統合の301元 | 42 | **全件 301** | ✓ |
| projects 一覧除外（noindex だがページは残す方針） | 41 | **全件 200** | ✓ 設計どおり |

7/30〜8/9 に実施した projects の301統合・非表示化が404に化けている、という懸念は**否定された**。

### 1-2. sitemap に載っているのに404を返すURLはあるか → **0件**

sitemap は 12,235 URL（sitemapindex 経由で全数取得）。

まずビルド生成物と静的に突合し、「生成物に見当たらない」7,293件を洗い出した。
内訳は `/grid` 7,192件・`/projects` 48件・`/subsidies` 33件・`/news` 10件・`/explainer` 9件で、
**これらは ISR（初回アクセス時生成）ルートであってビルド時に出力されないだけ**である。

そのうえで実応答を測定した。

| 母集団 | 件数 | 結果 |
|---|---:|---|
| ビルド生成物に無い（非grid）＝全数 | 101 | **全件 200** |
| ISR `/grid` 無作為 | 400 | **全件 200** |
| ビルド済 無作為 | 300 | **全件 200** |

→ **sitemap 掲載URLの404は 0件**。

> 計測上の注意（自戒）: 最初に並列10で HEAD スイープしたところ 175件が「応答なし」になったが、
> これは当方の並列度が高すぎたための計測失敗であり、404ではなかった。
> 並列3・3回リトライで測り直したところ **700/700 が 200** だった。
> 並列スイープの失敗を404と読み違えないこと。

### 1-3. sitemap の衛生（301元や除外が sitemap に混じっていないか） → **良好**

| 対象 | sitemap 掲載 |
|---|---:|
| glossary 301元 143件 | **0件** |
| projects 301元 42件 | **0件** |
| projects 一覧除外 41件 | **0件** |

### 1-4. 旧URL設計の残骸 → **404で正しい（②）**

`/about/chikudensho`・`/markets/grid-battery`・`/explainer/how-to-start`・`/subsidies/grid`、
および `/glossary/index`・`/projects/index`・`/news/index`・`/operators/index`・`/faq/index`・`/tools/index` の10件が404。

**ただしこれらは当方が「あり得そうな旧URL」として当てにいったプローブであり、GSC が実際に404と報告しているURLではない。**
外部から参照されている証拠は確認していない。

### 1-5. news の除外URL

`news-excluded.ts` に列挙された88件を測定した結果、**200が43件・404が45件**。
404の45件は microCMS 側に実体が無い（あるいは公開されていない）ものであり、
一覧からも詳細からも参照されない。誤って関連リンクに出していた42件は commit `c63336b` で解消済み。

### 1-6. ★410 Gone のメカニズム（主犯の候補） → **実証済み**

`src/middleware.ts` は、`/news/news-2026-{数字}-*` の形をしたパスのうち
`src/data/legacy-news-allowlist.json`（**28件**）に無いものへ **410 Gone** を返す。

```
/news/news-2026-05-01-test   → 410
/news/news-2026-01-15-sample → 410
/news/news-2026-12-31-x      → 410
```

合成した存在しないURLでも410が返ることを実証した。
**Google は 410 を「見つかりませんでした（404）」に合算して報告する**ため、
旧slug体系で公開・インデックスされていたURLの数だけ、GSC の404件数が積み上がる。

これは「消したので二度と来なくてよい」という意思表示として **410 は 404 より適切**であり、**設計どおり**である。

## 3. 実害の評価

**実害は小さい。** 理由は3点。

1. **③がゼロ**。クロール対象として自ら申告しているURLは、1件も404を返していない
2. **①もゼロ**。統合した旧URLはすべて301で価値を引き継いでいる
3. **②の中心は410**＝「意図的に削除した」とGoogleに正しく伝えている状態であり、
   これを404扱いで積み上げるのはGSCのレポート仕様によるもの。**放置してよい**

GSC の「見つかりませんでした（404）」は、**サイトの健全性を測る指標としては解釈に注意が必要**で、
件数そのものより「sitemap掲載URLが404でないか」「301すべきURLが404になっていないか」が実質的な健全性指標である。
本調査ではその2つがいずれもクリーンだった。

## 4. 次便で決めたいこと（今回は修正しない）

1. **410 を維持するか、301 に切り替えるか**
   旧 `/news/news-2026-*` に相当する現行記事がある場合は301の価値があるが、
   28件のallowlist以外は「そもそも残す価値がないと判断した記事」なので、**410維持を推奨**する。

2. **旧URL残骸への301追加（任意・低優先）**
   下記は301先が実在する（すべて200を確認済み）。外部リンクが確認できた場合のみ追加すれば足りる。

   | 旧URL | 301先候補 |
   |---|---|
   | `/markets/grid-battery` | `/grid` |
   | `/explainer/how-to-start` | `/explainer` |
   | `/subsidies/grid` | `/subsidies` |
   | `/about/chikudensho` | `/about` |
   | `/{glossary,projects,news,operators,faq,tools}/index` | 各ハブ |

   ※ ただし **これらは当方のプローブであり、実際に参照されている証拠はない**。
   GSC の404URL一覧と突合してから判断するのが順当。

3. **GSC の404URL一覧のエクスポート**
   1,086件の内訳を実測で確定させるには、これが唯一の道。いただければ本レポートの分類に機械的に当てはめられる。
