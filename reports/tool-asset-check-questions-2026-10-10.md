## (2) 配点案と画面の構成案

### 配点（便の案に「該当しない」を足す）

| 回答 | 点 | 扱い |
|---|---|---|
| はい（整備済み） | 1 | 「無いと確かめた」「要らないと確かめた」「区域外と確かめた」も「はい」 |
| 不明 | 0.5 | 条件に当たるか分からないときも「不明」（「該当しない」ではない） |
| いいえ（未整備） | 0 | |
| 該当しない | — | **分子からも分母からも除く**。当てはまる条件がある 19 問にだけ出す |

- 軸の値＝（該当する問いの点の和）÷（該当する問いの数）× 100%。重み付けは置かない（一次が無い・便のとおり）。
- **全問が「該当しない」の軸は 0% でも 100% でもなく「対象外」**と出す（レーダーではその頂点を灰色で「対象外」。0 除算で NaN を出さない）。
- 各軸に「**該当 n 問中**」を併記する（n が 1〜2 だと 0／50／100% に振れやすい）。「該当しない」にした問いは、未整備・不明の一覧とは別に「該当しないとした問い（条件つき）」として並べる（乱用で割合が上がるのを見えるようにする）。
- 「有無・要否を確かめた。ある・要る場合は控えがある」型（A3・G1・H1・H5・H8）と「区域外と確かめた」型（C1〜C4・C6）には「該当しない」を出さない。無い・不要・区域外と確かめた時点で「はい」。
- 二つの事柄を含む E6 は「両方そろって はい」・片方だけなら「いいえ」（各問の「答え方」）。
- 数値入力（保証の %・騒音の dB・浸水深など）は入れない。値の大小が水準の評価として読まれる（E 軸の調べで稼働可能率などの数値入力を同じ理由で落とした）。

### 画面の構成

1. 冒頭 1 行: 「**評価・格付けではありません。買い手・貸し手・保険者が確かめる項目の棚卸しです。**」（便のとおり）＋「入力はこの画面の中だけで使い、保存も送信もしません」（fire-risk-check と同じ）。
2. （任意・裁定 R2）採点しない前提の質問 **9 つ**で「該当しない」を自動で決める: 運転を始めたか／連系の電圧（低圧 10kW 未満・低圧 10kW 以上・高圧・特別高圧＝D1・D4・D5）／土地の権利（所有・賃借・地上権・その他＝F7 は賃借、F8 は賃借か地上権）／運用をアグリゲーターに委託しているか／O&M を外部に委託しているか／参加している市場（需給調整・容量・なし）／加入している保険（財物・事業中断・なし）／発電事業の届出をしているか（H3 の条件）／長期脱炭素電源オークションの応札・SII 補助の有無（A2）。自動で決めた分も利用者が変えられるようにする。
3. 設問: 軸ごとのタブかアコーディオン（**初期 DOM に 40 問の文を全部載せる＝#107**。表示の切り替えで畳む）。各問に「なぜ確かめられるか」と一次へのリンク（開閉）。
4. レーダー（8 軸・0〜100%・「該当 n 問中」・「対象外」の頂点は灰色）。説明文に「値は整備済みの割合で、良し悪しではありません」。
5. 未整備と不明の一覧（各問の「次にやること」と一次へのリンク）／該当しないとした問いの一覧（条件つき）。
6. 関連: 台帳テンプレート `/tools/asset-ledger`（整備の記録先。40 問の多くは台帳の列に対応）・火災 DB `/incidents`・変電所 DB `/grid`（D7）・fire-risk-check・用語集。
7. **fire-risk-check へのリンクの断り**: セル化学（cell-1）・賠償保険（emergency-4）・電気主任技術者（operation-5）・消防の届出（emergency-2）・離隔（building-1）は fire-risk-check に任せる。ただし fire-risk-check は **0〜10 点の格付け型**なので、「リンク先は点数を付けるツールで、この棚卸しとは別」と書き、その点数を asset-check に持ち込まない。(6) の誤りの是正（R6）を先にするのが望ましい。
8. 紛れやすい 2 組を画面で区別する: **D7（変電所ごとの公表値）と D4・D5（自設備の接続条件）**。/grid の「N-1 電制 未算定・公表なし」は「不可」と読まない（n1-status の 4 値）。`src/lib/grid-connection-checker.ts` の feasibility_score は当サイト独自の評価式なので、asset-check では使わない。C2 の「区域外」は「浸水の危険が無い」ではない（区域は各条第1項の河川・施設についてだけ指定される）と注記する。

### 否定テストの案（便 F 用・`scripts/verify-asset-check.ts`）

- 全部「はい」→ 各軸 100%／全部「不明」→ 50%／全部「いいえ」→ 0%（便のとおり）。
- 全部「該当しない」（出せる問いだけ）→ その軸は「対象外」表示（NaN・0% にならない）。「該当しない」を 1 問含む軸の割合の検算。
- **3 択の 21 問**（判定は `options` の数で行う。`applies_when` の文頭では判定しない）に「該当しない」の選択肢が出ない。
- リポ内の一次（`repo_ref` の path と行番号）の行に、data の逐語が今もある（台帳の改版で行がずれたら落ちる＝検出したい。本便で 46 か所とも一致を確認済み）。
- 初期 DOM に 40 問の文が全部ある（`<!-- -->` を剥がして数える・鉄則 #5）。
- 初期 DOM（と結果の表示）に、順位・格付け・良い／悪い・点数の評語が無い（禁止語の一覧で検査。fire-risk-check の「低リスク」「緊急対応必要」のような語を持ち込まない）。**社名の検査の範囲**: 比較の対象になりうる蓄電所の事業者・メーカー・アグリゲーターの名前を出さない。一次の発行元として「なぜ」と出典に出る名前（官公庁・OCCTO・EPRX・一般送配電事業者・保険会社・銀行・投資法人・自治体＝B7 の東北電力ネットワーク、F5 の三菱UFJ銀行、G1・G4 の東京インフラ・エネルギー投資法人、G2・G4・G5 の三井住友海上・東京海上日動 など）は許可一覧に入れる → 裁定 R9。
- 入力の保存なし（localStorage・cookie・fetch／sendBeacon を使っていない＝ソースの grep）。
- 一次の URL が 200 かの確認は**ネットワークを使うので prebuild に入れない**（METI・enecho の WAF が 202 を返して落ちる）。別のスクリプト（例 `verify:asset-check:urls`）にして手で回す（#meti-bot-challenge）。

## (4) 前提違い

### 依頼書の「一次の当て先」・「見るもの」と、一次で確かめた結果が違ったもの

（逐語は e-Gov などを 2026-10-10 に取り直したもの。調べ・検証・批評の記録から）

- **B「電気工事業法」**は蓄電所の工事に及ばない。電気工事業法 第2条第1項「この法律において「電気工事」とは、電気工事士法…第二条第三項に規定する電気工事をいう。」、電気工事士法施行規則 第1条の2「…発電所、蓄電所、変電所、最大電力五百キロワット以上の需要設備…」（自家用電気工作物から除くもの）。施工者の資格は建設業の許可（B3）で問うた。
- **B「電力会社の系統連系技術要件（公開の連系規程）」**に試験・竣工の定めは無かった。東京電力パワーグリッドの系統連系技術要件（令和8年10月1日・11月1日実施）で「試験」「竣工」「立会」「成績」は 0 件。「連系試験」「受入試験」は取得した一次に無い語で、法令の語は建設業法 第19条第1項第11号の「完成を確認するための検査」（B4・B5）。連系で出す書類は各社の申込書類一覧にある（B7・確かめたのは東北電力ネットワーク 1 社）。
- **A「JEM 規格」**: JEMA の「JEM 新発電システム」一覧（8 件: JEM 1493・1495・1498・1505・1508・1509・1515・1523）に系統用蓄電システムの容量・騒音のものは見つからなかった。JEM 1511（検索では低圧蓄電システムの初期実効容量）の推測した URL は 404 で、JEMA のページでは確かめていない。騒音の一次は電技省令 第19条第11項・騒音規制法・SII 公募要領にした（A5）。
- **A「消防法 危険物規制（リチウムイオン蓄電池の指定数量）」**: 指定数量は電池ではなく危険物ごとに決まる（消防法 第9条の4「危険物についてその危険性を勘案して政令で定める数量（以下「指定数量」という。）」）。蓄電池設備に当たる区分は危険物の規制に関する政令 第19条第2項第9号「危険物を用いた蓄電池設備以外では危険物を取り扱わない一般取扱所」。A 軸は fire-risk-check と重なるとして、H 軸は当てはめを確かめられないとして、どちらも落とした（設問にしていない）。
